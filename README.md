## 界面维护检查

“阅读与来源”按实际被专题引用的来源建立索引，可搜索作者、题名、核读范围或关联专题，按板块筛选和分页；来源卡片分别展示核读范围与用于哪些专题，支持进入精读。标记后保留展开和返回焦点；`/`在此页进入来源搜索。原14项主题阅读独立保留，不与专题出处混为同一层次。`tests/browser-sources.cjs` 检查完整来源分页、筛选/清除、核读范围、空结果、精读与焦点、五篇内容及新ID保存。来源数量不等于通读原著数量，也不证明所有观点由同一来源直接支持。

知识点库目录采用六个板块分组，数量从实际条目派生；主题内显示个人已熟悉数，各篇核验状态另列。标记或导入记录后更新文字，保留已展开分组和阅读返回位置。三个思想史扩展点为 `history-taylor-scientific`、`history-gulick-urwick`、`history-follett-integration`，仅按所列原典范围核验，不能当作这些作者全部思想已覆盖。`tests/browser-history.cjs` 检查三篇原典专题、章节链接、别名/作者搜索、目录、导入同步、个人记录与代表性版式。

地图详情顶部的“这个主题怎样学”提供本节点全部细分知识点和直接精读入口，分别显示个人自评与内容核验数量；原先下方的折叠入口由此替换，正文仍可在精读与知识点库中查看。继续入口优先薄弱点、再选尚未熟悉内容，全篇已熟悉时可回顾，不增加存储格式或自动进度。章节ID、原点ID及数据键保持稳定。`tests/browser-map-reading.cjs` 检查全部36个主题入口、优先规则、焦点、标记保存、组合搜索、既有章节链接和代表性布局。

复习看板优先展示细分知识点的“需要巩固”和“收藏待学”精读清单，每组最多显示6篇，记录更新时间较早者在前，无有效日期者在前；该日期不是最近阅读时间。收藏待学只含已收藏且自评未开始的条目，已熟悉及需巩固点不重复进入。标记改变后清单同步刷新，条目消失时退出精读将焦点返回复习标题。核心节点进度与笔记独立保留。`tests/browser-review.cjs` 使用下述浏览器环境验证空清单、排序、进入精读、自评移除、筛选跳转、焦点、个人数据保存和手机/平板/桌面版式。

学习路径的精选精读入口保存在 `content/research.json` 的 `readingPaths` 字段，包含建议衔接理由、读后问题及框架节点。十条路线共49个精读步骤，次序属于站内学习建议，不是严格学术前提或完整课纲。路径进度从原有知识点自评派生，不增加存储格式；仅打开文章不会改变掌握状态。继续入口优先返回路线内的需巩固点，再进入尚未熟悉的条目；全篇已熟悉时提供回顾。框架节点仍可从展开区返回地图。运行 `node tests/reading-paths.mjs` 验证数据与核验范围；`tests/browser-paths.cjs` 验证快捷跳转、进度不随浏览改变、标记保存、焦点恢复及代表性尺寸，环境与其他浏览器检查相同。

知识点库卡片显示内容核验状态、学习层级、所属主题、学习重点与篇幅；这些内容状态与卡片底部的个人收藏、掌握状态独立。顶部概况按结构化数据统计核验范围，库内不重复展示核心节点进度。内容状态支持正文与专题已核验、有专题、正文待核验筛选；清除筛选同时重置模块、类型、关键词、内容、层级及个人状态，并将焦点返回搜索框。`tests/browser-library.cjs` 检查组合筛选、统计与个人进度独立、主题搜索、阅读与保存及代表性尺寸；运行方式与下方浏览器检查相同。

精读界面现将专题摘要和可展开的章节目录放在顶部，桌面侧栏附完整专题入口。正文与专题自测的篇幅估算包含补充内容；来源范围、自测答案和关系说明分别展示。章节数据可选用 `table: {caption, headers, rows}` 存放有比较价值的表格；表格文字纳入全文搜索，手机上在表格区域内横向滚动。`tests/browser-reader-content.cjs` 检查新内容、专题目录、表格、别名搜索、全部精读包装渲染和代表性宽度，运行环境与下方导航检查一致。

`tests/browser-navigation.cjs` 使用独立临时浏览器数据，检查四个主页面在390、768、1024px宽度的切换和整页溢出，以及精读目录与专题深链接焦点、收藏/状态操作后的焦点、筛选后条目消失的焦点退路和退出精读的焦点恢复。需将 `ATLAS_PLAYWRIGHT` 设为已安装的 Playwright 模块路径、`ATLAS_BROWSER` 设为测试浏览器可执行文件路径，再运行 `node tests/browser-navigation.cjs`。可将 `ATLAS_AUDIT_ARTIFACTS` 设为截图输出目录，便于视觉抽查。检查使用本地临时服务，结束时关闭服务和浏览器，不读取用户浏览器资料。

正文目录及专题目录跳转会将键盘焦点移到目标章节，减少动态重绘造成的焦点丢失；目录滚动遵循系统的减少动画偏好。这些检查覆盖代表性交互，不等于完整无障碍认证。

## 持续建设批次

发布前运行 `python scripts/package-codex-source.py`（Windows 可用环境中实际的 Python 路径），脚本会根据11个静态资源的内容更新 `dist/index.html` 中的版本参数，再生成源码包，避免浏览器混用旧正文和新专题。随后运行 `node tests/asset-versions.mjs` 检查资源参数与文件内容一致；之后若修改了任何资源，必须再次执行打包并在最终提交后按 Sites 流程发布。

知识地图下方的“知识点关系图”集中展示已有专题中附解释的前置、组成、对照、争论和应用关系，可按类型、知识点、名称或别名筛选，并跳转到精读。箭头表示记录方向；前置关系的右侧是建议先学的内容。它目前只包含已整理关系，不代表所有知识点均有关系或目标正文均已核验。实现位于 `dist/relations.js`，数据来自 `content/research.json`，关系检查为 `node tests/relations.mjs`。

当前在原有108个细分点之外新增有独立稳定 ID 的知识点；数量以页面和覆盖清单为准，不再假定每个节点只有3个。扩展数据保存在 `content/expansion.json`，执行 `node scripts/build-expansion.mjs` 生成 `dist/expansion-data.js`；带来源的专题保存在 `content/research.json`，执行 `node scripts/build-research.mjs` 生成页面数据，再执行 `node scripts/create-coverage.mjs` 更新覆盖矩阵。不要改动或重用旧 ID，以保留学习记录。正文待核验筛选与有已核验专题筛选可以重叠：已有补充的旧正文仍可能待核验。
